`Grib2Summary.variable_for` now names a message ecCodes has no short name for as the GRIB2 reader does, `parameter_<discipline>_<category>_<number>` or the MRMS product, so the name it returns is a variable in the opened Dataset; each inspected `GribMessage` carries that name as `base_name`. For a selector that fetched a message holding several fields, such as RAP's wind components, it now raises and lists their variables instead of returning the first one.
