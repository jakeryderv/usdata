Upstream failures from `epa:aqs-daily`, `fema:disaster-declarations`, and `usgs:earthquakes` now exit 4, not 2. An AQS HTTP error whose body gives no header reason, such as a 503 maintenance page, stays an HTTP error instead of becoming `AqsError`, and a response that is not the JSON or count the service promises raises `httpx.DecodingError` instead of `QueryError` or `JSONDecodeError`. An AQS refusal with a header reason, such as a bad key, is still an `AqsError` and exits 2.
